# Citas: lista única y disponibilidad secundaria

6 de noviembre de 2026. Rama `local/pro-suite-no-push`, base `06b70019de69bb4e1ee46ead3eda22eedf05f7d0`. Solo checkout Pro. Sin push, producción, comunicaciones reales ni cambios en registros existentes.

La pantalla principal contiene Nueva cita, estados Pendientes/Confirmadas/Finalizadas/Canceladas/Todas y una sola lista paginada. Cada tarjeta indica si es solicitud del cliente o registro manual. La disponibilidad pública queda plegada como opción secundaria; el calendario solo aparece al configurar disponibilidad. Se conservan formularios, historial, reprogramación, cotizaciones y gestión de trabajos desde sus detalles. Al crear una cita manual, se abre el detalle guardado y se selecciona Confirmadas. Mis citas distingue las solicitudes hechas como cliente de las recibidas por el profesional.

La función local `pro_appointment_inbox`, de lectura, combina las tablas normalizadas sin consultar el documento de workspace. Excluye el trabajo que ya esté enlazado a una solicitud. Deriva el estado efectivo del registro asociado, ordena por fecha con desempate por origen/ID y devuelve 25 filas y cursor opaco. Las solicitudes sin horario utilizan su fecha de creación para ordenar; los registros manuales sin fecha válida usan epoch. No se reclasifican citas pasadas como finalizadas automáticamente.

El endpoint `/api/pro/appointment-list` reutiliza proApiAccess: desarrollo local, sesión, cuenta habilitada, membresía Pro y verificación administrativa cuando corresponda. El propietario siempre procede de la sesión; no se acepta un propietario del navegador. Valida estado y cursor. La función SQL solo puede ejecutarse con service_role y no escribe datos. Su instalación está añadida al bootstrap que rechaza destinos fuera de loopback; no es una migración hospedada. No se modifican RLS ni permisos de tablas.

BusinessPanel conserva sus formularios y detalles en modo dialogsOnly para reutilizar los guardados existentes. Las APIs de agenda anteriores siguen disponibles para detalle, edición y disponibilidad. El cliente sigue viendo sus propias solicitudes mediante el componente anterior.

Pruebas nuevas ES/EN: 55 citas con ambos orígenes y varias páginas, sin duplicar el trabajo de una solicitud confirmada; estados cerrados; cursores inválidos; acceso anónimo/sin Pro rechazado; otro profesional sin registros no obtiene datos al enviar el ID del propietario; RPC pública denegada; lista sin calendario principal; origen visible; filtro tras recarga; detalle y vuelta a la lista; creación manual con 120 minutos; todos los registros previos e historial de solicitudes/notificaciones idénticos. Se conserva la prohibición de descargar el workspace completo.

Se adaptan pruebas anteriores a los controles retirados: filtros por estado sustituyen vistas Calendario/Próximas; las aserciones de búsqueda, paginación y medianoche siguen en las pruebas de API de agenda. La edición diaria se comprueba dentro de Disponibilidad pública. No se retiran comprobaciones de datos, historial o navegación. La validación visual de esta revisión usa capturas de WebKit móvil; no se afirma una nueva prueba manual completa del simulador nativo.
